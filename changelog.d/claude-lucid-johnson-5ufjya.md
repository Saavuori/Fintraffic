### Added
- **Class B boats on the sea map**: Digitraffic only publishes class A AIS, so leisure craft and small work and fishing boats with class B transponders never appeared, even though they make up much of the summer traffic in the archipelago. With an [aisstream.io](https://aisstream.io) key set (`AISSTREAM_API_KEY`), the backend now also subscribes to aisstream's class B position reports and static data for the Baltic and puts those boats on the map with names, types and hull sizes as their reports arrive. They get trails and replay like any other vessel, and the "Sailing / Pleasure" filter covers them. On a midday test in October this added about 150 boats to the roughly 800 Digitraffic ships. Digitraffic stays the only source for every ship it reports, so the two feeds never fight over a position, and aisstream's static data only fills fields Digitraffic leaves empty. The vessel panel shows hull size from aisstream when Digitraffic has none, and shows "Not reported (class B)" in place of AIS's meaningless "Undefined" status.

### Notes
- **Ops: the aisstream.io key is a secret and lives only on the host**: the compose file reads it from `~/fintraffic/.env` (mode 600) via `${AISSTREAM_API_KEY:-}`; `AISSTREAM_API_KEY=… ./install.sh` stores it there once, and the update cron reuses it. Without a key the feed is simply off. `/api/health` reports `aisstream_enabled` / `aisstream_connected` / `aisstream_vessels` under `modes.meri` without ever degrading the mode, and `/metrics` counts messages by type in `fintraffic_meri_aisstream_messages_received_total`.
